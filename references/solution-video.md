# 答案讲解片（90–150 秒）

## 目标

让观众看懂三件事：

1. 代码每一步在做什么
2. 变量/数组怎么变
3. 为什么这么写，边界在哪

## 推荐结构（90 秒）

| 时间 | 内容 | 画面 |
|---|---|---|
| 0–8s | 这份代码分几步 | 代码全貌 + 三步骨架 |
| 8–30s | 第一步：统计/初始化 | 代码高亮 + 数组桶/变量 |
| 30–45s | 为什么这么写 | 两张“为什么”卡 |
| 45–70s | 主循环/核心操作 | 当前行高亮 + 状态逐位变化 |
| 70–85s | 边界与坑 | 溢出对比、空输入、前导零 |
| 85–90s | 总结 | 三步口诀卡 |

## 必须有的三类画面

### 1. 代码面板

- 左侧固定代码，行号 01–15
- 当前行高亮条，跟着口播移动
- 语法高亮但不要太多颜色（关键字蓝、类型青、字符串橙、注释灰）

### 2. 状态可视化

至少选一种：

- 数组桶：每个下标一个格子，显示计数
- 字符串扫描：字符逐个高亮
- 栈/队列：元素进出
- DP 表：单元格逐格填
- 图：节点/边变色

数组类题优先做“计数 + 飞入 + 闪光”，详见 `visual-grammar.md`。

### 3. 错误写法对比

如果题目有典型坑，必须给一张对比卡：

```text
int res = res * 10 + d;     ✗ 溢出
string res; res += char;    ✓ 任意长度
```

## 讲“为什么”的方式

不要只说“这样写是对的”。用三种证据：

- **不变量**：循环每轮结束时，什么一定成立
- **极端样例**：全是 0、只有一个数字、最大数据
- **反例**：如果少用一个数字/顺序反过来，会怎样

## 边界清单

- 答案长度是否会超过 18 位 → 用 `string`
- 前导零是否会出现
- 空输入/只有一个字符
- 最大数据下的时间/空间
- 相同元素、重复计数

## 检查

```bash
python scripts/check_gates.py ./work/solution
```

门禁会提示常见危险写法（如 `int` 存大数），但最终仍要人工确认参考代码正确。
