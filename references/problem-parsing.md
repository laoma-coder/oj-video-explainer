# 拆题：把题面变成可拍的结构

## 目标

把题目整理成一份 `problem.md`，后续两条视频都只依赖它。

## 必填字段

```markdown
# 题目信息

- 平台：
- 题号：
- 题目名：
- 难度：
- 来源（比赛/年份）：
- 一句话任务：

## 输入

## 输出

## 数据范围

## 样例

| # | 输入 | 输出 | 解释 |
|---|---|---|---|

## 特殊性质

## 易错点（仅答案片使用）

## 做法关键词（禁止出现在题意片）
```

## 规则

1. **逐字抄约束**：`1 ≤ |s| ≤ 10^6` 不能写成“长度最多一百万左右”。
2. **样例保真**：空格、换行、大小写、标点都要保留。
3. **不补条件**：题面没说的“保证有解”“数据随机”“时间限制 1s”，不要自己加。
4. **区分“题意”与“做法”**：
   - 题意：给了什么、能做什么、要求什么
   - 做法：怎么统计、怎么排序、用什么数据结构
5. **答案不确定时先标问号**：不要为了视频顺滑而编造。

## 从 HTML/截图里提题的技巧

- 优先找 `【题目描述】`、`【输入格式】`、`【输出格式】`、`【数据范围】`
- 题目数据常藏在 `const LESSON = {...}` 或 `problem` 字段里
- 复制后先跑一遍样例，确认没有把 `0` 和 `O`、`1` 和 `l` 弄混

## 输出物

- `problem.md`
- 一句话题意（≤ 30 字）
- 3 个“观众可能误解的点”
- 3 个“题意片不能出现的词”
